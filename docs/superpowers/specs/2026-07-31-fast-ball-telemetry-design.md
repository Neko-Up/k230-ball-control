# K230 320×320 快速钢球检测与实时遥测设计

## 目标

在不降低 LCD 和 VLC 图传清晰度的前提下，提高钢球检测与控制数据刷新率，并在 LCD 上持续显示钢球位置、轴向速度和当前识别帧率。

## 数据通道

- GC2093 保持 1920×1080@30 输入。
- LCD 与 H.264/VLC 保持现有高清通道及输出配置。
- AI/传统视觉通道改为 320×320 RGB888P。
- KPU 模型输入固定使用部署配置的 320×320；程序启动时校验模型输入，配置不匹配则打印明确错误并停止控制输出。
- 绿色管道检测、球检测、跟踪与预测统一在 320×320 坐标系运行。

## 坐标与控制

- 管道 ROI、绿色轮廓、中心轴和球心全部使用相对比例或按 640→320 等比例换算后的常量。
- LCD 绘制通过 `ai_to_disp()` 从 320×320 映射到显示分辨率。
- 厘米标定仍由管轴有效长度换算，降低像素分辨率不会改变厘米坐标定义。
- 钢球速度按相邻有效测量的厘米位置差除以真实 `ticks_ms` 时间差计算，单位 cm/s。
- UART 继续每个有效控制帧发送最新位置与速度，不等待 LCD 或性能统计窗口。

## LCD 遥测

LCD 右上区域持续显示：

- `P:+0.00cm`：球相对原点的有符号位置；
- `BV:+0.0cm/s`：球沿管轴方向的有符号速度；
- `AI:00.0FPS`：最近短窗口内的实际控制/识别帧率。

当球或管道无效时，位置和速度显示为无效状态，控制输出保持现有安全策略。

## 性能统计

- 使用固定短窗口统计 FPS，避免单帧抖动导致数字乱跳。
- 窗口结束后只更新一个全局遥测值，不在每帧分配列表或字符串。
- 串口保留周期性性能日志，但 LCD 使用缓存值，避免阻塞控制路径。

## 兼容性与错误处理

- 不改变 D36A、MS42CG、触摸标定、UART 协议和 H.264/VLC 架构。
- 保留 KPU + 绿色 Blob 混合追踪状态机。
- 模型输入不是 320×320时拒绝带错误尺寸运行，避免框坐标失配。
- 坐标缩放采用集中辅助函数和按图像尺寸生成的 ROI，避免散落硬编码。

## 验证

- 单元测试覆盖 320 坐标缩放、ROI 边界、FPS 窗口、厘米速度和 LCD 遥测格式。
- 全量 pytest、Python 语法检查与 `git diff --check` 必须通过。
- 板端验收：硬复位后可启动；LCD/VLC正常；球位置、速度和FPS持续显示；UART刷新不低于检测帧率；软停止后重新运行不会出现 IRQ 注册失败。
