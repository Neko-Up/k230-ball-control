# K230 H.264 圆形标记图传设计

## 目标

将钢球检测标记由矩形改为动态圆形，并将当前 WBC+MJPEG 图传替换为 WBC+硬件 H.264+RTSP，使 VLC 能实时看到包含圆形标记的合成画面，同时优先保证钢球坐标反馈频率。

## 功能边界

- 保留现有 kmodel、AI2D、KPU 后处理、校准、Wi-Fi 自动选信道和 UART 协议。
- UART 继续在每个 AI 帧发送，不因显示或图传降频。
- 删除 MJPEG HTTP 服务，不同时运行 MJPEG 和 RTSP。
- VLC 通过启动日志打印的 RTSP URL 显示并录像。
- `main.py.autosave` 不纳入版本控制。

## 圆形标记

- 圆心取检测框中心：`cx = bx + bw // 2`，`cy = by + bh // 2`。
- 半径取检测框长边一半并增加 3 像素余量：`max(4, max(bw, bh) // 2 + 3)`。
- 保留置信度文字、校准圆、轨迹线和其他 OSD。
- 仅改变显示形状，不改变检测框、目标筛选或跟踪数据。

## 视频链路

- WBC 捕获 LCD 视频层与 OSD 层的合成画面，确保圆形标记进入图传。
- 使用 K230 硬件 Encoder 输出 H.264 Main Profile。
- 输出分辨率 800x480，目标帧率 15 FPS，码率约 1 Mbps，GOP 15，无音频。
- 独立线程读取 WBC 帧、编码、取得码流并调用 RTSP API 发送。
- RTSP 服务使用端口 8554，单会话名称 `ball`。

## 控制优先调度

- AI 推理和 UART 坐标输出每帧运行。
- OSD 每 2 个 AI 帧更新一次，减少绘制与显示提交开销；视频仍以约 15 FPS 捕获最近一次合成画面。
- GC 保持每 60 帧执行一次。
- 性能日志继续每 60 个 AI 帧输出一次。

## 启动与故障隔离

1. 初始化模型、摄像头、显示、H.264输出缓冲和媒体管理器。
2. 摄像头和首个 AI 帧正常后启动 Wi-Fi。
3. Wi-Fi 成功后启动 RTSP/H.264线程并打印 VLC 地址。
4. Wi-Fi、编码器或 RTSP 初始化失败时记录错误并继续 AI、LCD和UART。
5. 退出时依次停止 RTSP线程、WBC、编码器、摄像头、显示和媒体管理器。

## 验收标准

- 主程序通过 Python 语法解析和静态接口检查。
- 检测结果使用动态圆形标记，不再绘制钢球检测矩形。
- UART消息格式保持 `X:{:+04d},Y:{:+04d}`。
- VLC 能通过打印地址打开 H.264 RTSP流，画面包含圆形标记。
- UART坐标更新频率不低于改动前；RTSP失败不会终止识别控制。
- 本地验证后提交并推送到私有仓库 `Neko-Up/k230-ball-control`。

## 自审

规格没有待定项；控制、显示和网络频率边界明确。硬件运行结果必须在K230上验证，桌面端只能验证语法、静态结构和Git差异。
