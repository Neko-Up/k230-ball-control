# K230 H.264 Circle Stream Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show a dynamic circular ball marker in VLC through H.264/RTSP while preserving full-rate AI inference and UART control feedback.

**Architecture:** Keep the existing single-file CanMV application. WBC captures the LCD camera layer plus OSD, a hardware H.264 encoder runs in a separate RTSP thread at 15 FPS, and the AI loop continues to process and transmit coordinates every frame while OSD rendering is throttled to every second AI frame.

**Tech Stack:** CanMV K230 MicroPython v1.8, `media.vencoder`, `multimedia.rtsp_server`, WBC display capture, KPU/nncase, UART, VLC, host-side Python static tests.

## Global Constraints

- Preserve the current kmodel, AI2D, KPU post-processing, calibration, Wi-Fi startup channel selection, and UART payload `X:{:+04d},Y:{:+04d}`.
- Use WBC so the RTSP stream contains the circular OSD marker.
- Use H.264 Main Profile at 800x480, 15 FPS, about 1 Mbps, GOP 15, with no audio.
- Do not run MJPEG and RTSP together.
- Keep AI and UART processing every frame; update OSD every 2 AI frames.
- RTSP failure must not terminate AI, LCD, or UART.
- Never stage or commit `main.py.autosave`.
